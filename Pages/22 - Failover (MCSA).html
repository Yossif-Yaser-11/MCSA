Failover Clustering - التوافر العالى

شرح نظري وتطبيق عملي لإدارة Windows Server.

العودة إلى فهرس الدروس

الـ Failover Clustering بيخليك تشغّل خدمة على أكتر من سيرفر. لو سيرفر وقع، الخدمة بتنتقل تلقائياً للسيرفر التانى من غير انقطاع يذكر.

مكونات الـ Cluster

  • Cluster Nodes: السيرفرات اللى بتكوّن الـ Cluster (الحد الأدنى 2)
  • Shared Storage: تخزين مشترك بين الـ Nodes (SAN أو iSCSI)
  • Cluster Name: اسم افتراضى للـ Cluster
  • Cluster IP: عنوان IP افتراضى
  • Witness: جهة ثالثة للتصويت عند الخلاف

Quorum

الـ Quorum هو الحد الأدنى من الـ Nodes اللى لازم تكون شغّالة عشان الـ Cluster يشتغل. بيمنع الـ Split-Brain (كل Node تفتكر إنها المسؤولة).

  • Node Majority: أكتر من نص الـ Nodes لازم يكونوا شغّالين
  • Node + Disk Witness: بيستخدم قرص مشترك كـ Tiebreaker
  • Node + File Share Witness: بيستخدم Shared Folder كـ Tiebreaker
  • Cloud Witness: Azure Blob Storage كـ Witness

تثبيت وإعداد Failover Cluster

# تثبيت الـ Feature على كل الـ Nodes
Install-WindowsFeature -Name Failover-Clustering -IncludeManagementTools

# اختبار ما قبل الإنشاء
Test-Cluster -Node "SRV-NODE1","SRV-NODE2" -Include "Storage","Network"

# إنشاء الـ Cluster
New-Cluster -Name "CLUSTER-01" -Node "SRV-NODE1","SRV-NODE2" -StaticAddress "192.168.1.100"

# إعداد الـ Witness
Set-ClusterQuorum -Cluster "CLUSTER-01" -FileShareWitness "\\SRV-DC01\ClusterWitness"

Cluster Roles

# إضافة Role على الـ Cluster
# Cluster Manager → Configure Role → File Server, SQL, Hyper-V, etc.

# Hyper-V على Cluster (Live Migration)
# الـ VMs تقدر تنتقل بين الـ Nodes بدون انقطاع
Move-VM -Name "VM-Exchange" -DestinationHost "SRV-NODE2" -IncludeStorage -DestinationStoragePath "D:\VMs"

التطبيق العملى - Failover Clustering

تمرين 1: إعداد 2-Node Cluster

# على كلا الـ Nodes:
Install-WindowsFeature -Name Failover-Clustering -IncludeManagementTools

# إضافة iSCSI Storage
Start-Service MSiSCSI
New-IscsiTargetPortal -TargetPortalAddress "192.168.1.50"
Get-IscsiTarget | Connect-IscsiTarget -IsPersistent $true

# تهيئة الـ Shared Disk على Node1 بس
Initialize-Disk -Number 1 -PartitionStyle GPT
New-Partition -DiskNumber 1 -UseMaximumSize -DriveLetter Q
Format-Volume -DriveLetter Q -FileSystem NTFS -NewFileSystemLabel "Cluster_Quorum" -Confirm:$false

# اختبار
Test-Cluster -Node "SRV-NODE1","SRV-NODE2"

# إنشاء
New-Cluster -Name "FS-CLUSTER" -Node "SRV-NODE1","SRV-NODE2" -StaticAddress "192.168.1.100"

تمرين 2: إضافة File Server Role

# إضافة Role
Add-ClusterFileServerRole -Cluster "FS-CLUSTER" -Name "ClusterFS" -StaticAddress "192.168.1.101" -Storage "Cluster Disk 1"

# مشاركة مجلد
Add-ClusterSharedVolume -Name "Cluster Disk 2"
New-SmbShare -Name "ClusterShare" -Path "C:\ClusterStorage\Volume1\SharedData"

تمرين 3: اختبار الـ Failover

# من Cluster Manager:
# اعمل Pause ثم Drain على Node1
# الـ Resources المفروض تنتقل لـ Node2 تلقائياً

# أو من PowerShell:
Suspend-ClusterNode -Name "SRV-NODE1" -Drain
# تحقق إن الـ Roles انتقلت
Get-ClusterResource | Select Name, State, OwnerNode
