Rights Management Server - AD RMS

شرح نظري وتطبيق عملي لإدارة Windows Server.

العودة إلى فهرس الدروس

الـ AD RMS (Active Directory Rights Management Services) بيحمى المستندات والمحتوى الحساس حتى بعد خروجه من الشركة. بيتحكم فى من يقدر يقرأ أو يعدّل أو يطبع أو يفوّد المستند.

كيف يعمل AD RMS

  1. المستخدم بينشئ مستند ويحدد الصلاحيات (مثلاً: Ahmed يقدر يقرأ بس، Sara تقدر تعدّل)
  2. الـ RMS Client بيشفّر المستند ويحفظ الصلاحيات معاه
  3. لما حد تانى يفتح المستند، الـ RMS Client بيتصل بالـ RMS Server للتحقق من صلاحياته
  4. لو الشخص معهوش صلاحية، مش هيقدر يفتح المستند حتى لو نسخه

متطلبات AD RMS

  • Active Directory Domain Services
  • Microsoft SQL Server (للـ Database)
  • IIS
  • Certificate Authority
  • Service Account بصلاحيات محددة

التثبيت

# تثبيت الـ Role
Install-WindowsFeature -Name ADRMS -IncludeManagementTools

# إعداد RMS Cluster (من الـ GUI)
# Server Manager → AD RMS → Configure AD RMS
# اختار: Create a new AD RMS root cluster
# Database: SQL Server
# Service Account: رمس_السيرفر
# Cryptographic Mode: 2 (أأمن)

إنشاء Rights Policy Templates

# من الـ GUI: AD RMS → Rights Policy Templates
# New Template
# اسم: "Confidential - Read Only"
# إضافة Users/Groups
# تحديد الـ Rights: View, Print (بدون Edit, Copy, Forward)

# تصدير الـ Template للمستخدمين
# يتوزع تلقائياً عبر GPO أو يدوياً

استخدام RMS فى Office

فى Microsoft Word / Excel / Outlook:

  • File → Info → Protect Document → Restrict Access
  • اختار الـ Template المناسب أو حدد الصلاحيات يدوياً
  • المستند يتشفّر تلقائياً

التطبيق العملى - AD RMS

تمرين 1: تثبيت AD RMS

# قبل التثبيت: تأكد من وجود SQL Server
# إنشاء Service Account
New-ADUser -Name "RMS Service" -SamAccountName "svc-rms" -UserPrincipalName "svc-rms@networkat.local" -AccountPassword (ConvertTo-SecureString "RMS@Service123" -AsPlainText -Force) -Enabled $true -PasswordNeverExpires $true

# تثبيت الـ Role
Install-WindowsFeature -Name ADRMS, ADRMS-Server, ADRMS-Identity -IncludeManagementTools

# من الـ GUI:
# Server Manager → Notifications → Configure AD RMS
# الخطوات: Cluster → Database (SQL) → Service Account → Key Settings → Cluster URL → SCP

تمرين 2: إنشاء Rights Templates

# من AD RMS Management Console:
# 1. Rights Policy Templates → New Template
# Template 1: "View Only"
#   - Users: Domain Users
#   - Rights: View, ViewRightsData
#   - Expiration: 30 days
# Template 2: "Internal Use"
#   - Users: Domain Users
#   - Rights: View, Edit, Print
#   - No expiration
# Template 3: "Confidential"
#   - Users: GG_Managers
#   - Rights: FullControl
#   - No expiration

تمرين 3: اختبار الحماية

  1. افتح Word وابنى مستند حساس
  2. File → Info → Protect → Restrict Access → Restricted Access
  3. اختار Template "View Only" وحدد بريد المستقبل
  4. احفظ المستند وابعته للمستخدم
  5. المستخدم هيشوف بس مش هيقدر يعدّل أو ينسخ
